# DENTIX: подключение Doctors и Price к Google Sheets

Статус текущей сборки: `READY_FOR_GOOGLE_SHEETS_CONNECTION`.

Сайт уже умеет безопасно читать опубликованные строки из Google Sheets через публичный JSON endpoint Google Apps Script. Пока endpoint не настроен, при ошибке сети или при невалидных данных интерфейс автоматически использует локальные Doctors и Price. Booking/CRM к этой интеграции не привязаны и не меняются.

## 1. Структура таблицы

Создайте одну Google-таблицу с двумя листами. Названия листов и заголовки первой строки должны совпадать точно.

### Лист `Doctors`

| Поле | Обязательно | Назначение |
| --- | --- | --- |
| `id` | да | Стабильный ASCII id: буквы, цифры, `-`, `_`. Для существующих врачей: `laura-hrysiak`, `albert-podolyansky`, `olena-hamaza`. |
| `full_name` | да | Имя врача для карточки. |
| `role` | да | Подтверждённая специализация/роль. |
| `description` | нет | Только подтверждённый текст; поле можно оставить пустым. |
| `photo_url` | условно | Публичный прямой HTTPS URL. Для трёх существующих `id` можно оставить пустым — сохранится локальное официальное фото. Для нового врача URL обязателен. |
| `photo_alt` | нет | Доступное описание фото. |
| `sort_order` | нет | Число для порядка карточек. |
| `is_published` | нет | `TRUE`/`FALSE`; пустое значение считается `TRUE`. |

### Лист `Price`

| Поле | Обязательно | Назначение |
| --- | --- | --- |
| `id` | да | Уникальный стабильный ASCII id строки. |
| `category_id` | да | ASCII id секции; сохраняйте его стабильным для прямых ссылок. |
| `category` | да | Короткая подпись категории. |
| `category_title` | нет | Полный заголовок секции; при пустом значении используется `category`. |
| `service_name` | да | Название услуги из утверждённого прайса. |
| `price` | да | Цена как отображаемый текст, без вычислений на сайте. |
| `price_note` | нет | Дополнительная подтверждённая пометка. |
| `category_order` | нет | Число для порядка категорий. |
| `sort_order` | нет | Число для порядка строк внутри категории. |
| `is_published` | нет | `TRUE`/`FALSE`; пустое значение считается `TRUE`. |

Не добавляйте в таблицу диагнозы, результаты лечения, неподтверждённый стаж или медицинские обещания. Не переиспользуйте один `id` для разных записей: дубликаты отклоняются адаптером.

## 2. Публикация безопасного endpoint

1. В Google-таблице откройте **Расширения → Apps Script** и вставьте содержимое `Code.gs` из этой папки.
2. В **Project Settings → Script properties** добавьте `DENTIX_SPREADSHEET_ID` со значением ID таблицы из её URL. ID не нужно встраивать в клиентский код.
3. Выберите **Deploy → New deployment → Web app**; выполнение — от владельца, доступ — `Anyone`. Публикуется только содержимое двух вкладок, которое возвращает скрипт. Сама таблица остаётся редактируемой владельцами.
4. Откройте полученный URL, заканчивающийся на `/exec`, и проверьте JSON с массивами `doctors` и `price`.
5. Для локальной проверки создайте `.env.local` (он не коммитится):

   ```env
   VITE_DENTIX_CONTENT_API_URL=https://script.google.com/macros/s/DEPLOYMENT_ID/exec
   VITE_DENTIX_CONTENT_TIMEOUT_MS=4000
   ```

6. Для GitHub Pages создайте repository variable `VITE_DENTIX_CONTENT_API_URL` с тем же `/exec` URL и заново запустите workflow.

URL endpoint не является учётными данными: он попадает в браузерную сборку. Не помещайте в таблицу непубличные данные, секреты, API-ключи или персональные данные пациентов.

## 3. Контракт и отказоустойчивость

Endpoint возвращает объект вида:

```json
{
  "version": 1,
  "updated_at": "2026-09-03T12:00:00.000Z",
  "doctors": [],
  "price": []
}
```

Клиент принимает только опубликованные, полные строки, безопасные ASCII id и HTTPS-ссылки на новые фото. Doctors и Price валидируются независимо: если одна вкладка пуста или невалидна, только эта секция остаётся на локальном fallback. Таймаут, сетевой сбой, HTTP-ошибка или неверный JSON не ломают страницу.

Для подключения нужно передать разработчику только ID/ссылку таблицы с правом редактирования и опубликованный `/exec` URL либо предоставить доступ для настройки Apps Script. До этого сборка намеренно остаётся в статусе `READY_FOR_GOOGLE_SHEETS_CONNECTION`.
